# AI 业务接入说明

## 1. 文档定位

本文档说明远端 AI 在当前 `Smart Clock` 项目中的业务定位、数据边界与 Web 接口说明。

本文档关注的是：

- 远端 AI 参与了哪些业务功能
- AI 能读取哪些项目数据
- AI 在 `Web` 侧如何与页面和后端接口协作
- `/model` 页相关接口如何调用

如果只关心 OpenAI-compatible 协议层、API key 读取方式、模型解析规则与底层调用示例，请阅读 [docs/AI_use.md](./AI_use.md)。

## 2. AI 在项目中的业务角色

当前远端 AI 只参与 `Web` 控制中心中的两个业务功能，并且都位于 `/model` 页面：

1. 模型对话
2. 健康分析报告

AI 的首版角色是 `只读助手`，不具备直接修改项目运行配置的权限。

这意味着：

- AI 不直接修改 Todo
- AI 不直接修改闹钟
- AI 不直接修改语音设置
- AI 不调用设备控制类写接口

AI 只读取当前 Web 端已有的状态与摘要数据，然后返回结构化结果，供 Web 端展示或渲染。

## 3. AI 参与的两个业务功能

### 3.1 模型对话

用户在 `/model` 页面输入问题后，Web 后端会：

1. 读取当前设备状态摘要
2. 读取当前配置摘要
3. 读取当前连续在位时长
4. 读取当前未完成 Todo
5. 读取最近最多 `15` 条隐藏对话概括
6. 组装 prompt
7. 调用远端 AI
8. 返回用户可见回答
9. 额外保存一条用户不可见的“对话概括”

模型对话的定位不是通用闲聊，而是围绕以下主题的垂直助手：

- 当前环境状态
- 连续在位 / 久坐提示
- Todo 与工作节奏建议
- 办公健康与环境改善建议

对话风格要求：

- 简洁
- 自然
- 略带风趣

### 3.2 健康分析报告

用户点击“生成健康分析报告”时，Web 后端会：

1. 读取当前设备状态摘要
2. 读取当前配置摘要
3. 读取当前连续在位时长
4. 读取当前未完成 Todo
5. 读取少量关键设备事件摘要
6. 组装报告专用 prompt
7. 调用远端 AI
8. 获取结构化报告字段
9. 保存最近一份报告
10. 渲染在线预览
11. 支持导出 PDF

报告只在用户显式点击时生成，系统不会在后台自动调用 AI 周期性生成报告。

报告风格要求：

- 专业
- 严谨
- 稍微详尽
- 不说废话

## 4. AI 可读取的数据边界

### 4.1 模型对话可读取

- `device_status`
- `config_summary`
- `continuous_presence_duration_s`
- `open_todos`
- 最近最多 `15` 条 `dialog_memory_summaries`

普通对话不读取完整设备事件历史。

### 4.2 健康报告可读取

- `device_status`
- `config_summary`
- `continuous_presence_duration_s`
- `open_todos`
- `report_event_summary`

其中 `report_event_summary` 应由 Web 后端基于少量关键事件生成压缩摘要，而不是将完整事件历史直接交给 AI。

## 5. 对话记忆机制

### 5.1 为什么要保存隐藏概括

如果直接保存全部原始聊天记录：

- prompt 会持续膨胀
- 成本和延迟上升
- 普通聊天产品特征会压过本项目的垂直助手定位

因此，当前设计采用“隐藏概括记忆”机制：

- 每轮成功对话后，AI 除了返回用户可见回答，还会返回一条用户不可见概括
- Web 只长期保存这条概括
- 下次请求 AI 时，只带最近最多 `15` 条概括

### 5.2 用户可见聊天原文

用户可见聊天记录只保留在当前页面会话中，不在后端做长期归档。

### 5.3 清空对话缓存

`/model` 页面提供“清空对话缓存”按钮。

用户确认后，Web 后端会清空本地隐藏概括记录。该动作不会影响当前页面之外的其它业务数据。

## 6. 健康报告机制

### 6.1 报告生成方式

报告不是由 AI 直接输出完整 PDF 或完整 HTML。

正确链路是：

1. AI 返回固定 schema 的结构化字段
2. Web 后端根据字段套用固定模板
3. 页面做在线预览
4. PDF 导出复用同一份结构化报告

这样可以保证：

- 预览与 PDF 内容一致
- 导出不重复调用 AI
- 后端可以统一控制样式与字段展示规则

### 6.2 最近一份报告

系统只保存最近一份成功生成的报告。

- 生成成功：覆盖旧报告
- 生成失败：保留旧报告
- 导出 PDF：始终基于最近一次成功报告

## 7. AI 与项目现有数据文件的关系

当前 AI 业务会继续复用现有 Web 数据源：

- `web/data/device_status.json`
- `web/data/device_config.json`
- `web/data/todos_active.json`
- `web/data/event_history.json`

同时新增两份 AI 相关文件：

- `web/data/model_dialog_memory.json`
- `web/data/latest_health_report.json`

## 8. Web 接口说明

以下接口均服务于 `/model` 页面。

### 8.1 `POST /api/model/chat`

用途：发起一轮模型对话。

请求体：

```json
{
  "message": "我现在适合继续工作吗？"
}
```

成功响应：

```json
{
  "answer_text": "环境基本还行，但你已经连续在位较久，建议先起来活动几分钟。"
}
```

后端内部额外行为：

- 调用 AI
- 解析 `answer_text`
- 解析 `memory_summary`
- 将 `memory_summary` 追加保存到 `model_dialog_memory.json`

失败时：

- 不保存新的隐藏概括
- 返回错误响应

### 8.2 `DELETE /api/model/memory`

用途：清空本地隐藏对话概括。

成功响应：

```json
{
  "ok": true
}
```

说明：

- 该接口不会删除 Todo、事件、配置或报告
- 该接口只影响 AI 对话缓存

### 8.3 `POST /api/model/report/generate`

用途：生成并保存最近一份健康分析报告。

请求体可为空：

```json
{}
```

成功响应：

```json
{
  "generated_at": "2026-06-18T20:45:00+08:00",
  "render_version": "v1",
  "report_fields": {
    "report_title": "办公健康分析报告",
    "risk_level": "medium",
    "overall_summary": "当前环境基本可工作，但连续在位时长偏长。",
    "environment_analysis": "当前温湿度处于可接受范围，光照略弱。",
    "sedentary_analysis": "已连续在位约 3 小时，久坐负担明显上升。",
    "todo_and_routine_advice": "建议先安排一次短休息，再继续当前剩余任务。",
    "improvement_actions": [
      "先起身活动 5 到 10 分钟",
      "补充环境照明",
      "下一工作段控制在 45 到 60 分钟内"
    ],
    "key_findings": [
      "连续在位时长偏长",
      "环境光照偏弱"
    ]
  }
}
```

后端内部额外行为：

- 调用 AI
- 校验报告结构
- 保存 `latest_health_report.json`
- 覆盖旧报告

失败时：

- 不覆盖旧报告
- 返回错误响应

### 8.4 `GET /api/model/report`

用途：读取最近一份已保存报告，供页面刷新后重新展示。

成功响应：

- 返回最近一份报告对象

失败响应：

- 若当前没有报告，返回 `404`

### 8.5 `GET /api/model/report/pdf`

用途：导出最近一份报告的 PDF。

成功响应：

- 返回 PDF 文件流

失败响应：

- 若当前没有可导出报告，返回 `404`

说明：

- 该接口不重新调用 AI
- PDF 内容应与当前最新报告预览保持一致

## 9. 接口调用顺序建议

### 9.1 页面首次进入 `/model`

建议前端：

1. 初始化空聊天视图
2. 调用 `GET /api/model/report` 尝试读取最近报告
3. 若无报告，则只展示“生成报告”入口

### 9.2 用户发送对话

建议前端：

1. 禁用发送按钮
2. 调用 `POST /api/model/chat`
3. 收到响应后展示 `answer_text`
4. 恢复发送按钮

### 9.3 用户生成报告

建议前端：

1. 禁用生成按钮
2. 调用 `POST /api/model/report/generate`
3. 收到响应后刷新报告预览
4. 启用 PDF 导出按钮

### 9.4 用户清空缓存

建议前端：

1. 弹出确认
2. 调用 `DELETE /api/model/memory`
3. 成功后清空当前页的可见聊天区域

## 10. 错误处理原则

- AI 请求失败不能影响其它页面功能
- 对话失败时不写入隐藏概括
- 报告失败时不覆盖旧报告
- 用户界面提示应简短明确
- 详细错误信息保留在后端日志中
